# ThreadZero V7.4 — Unified Hybrid UX

Date: 2026-08-30
Version: V7.4
Project Mode: Product

## Project Lock

Project Name: ThreadZero V7.4 Unified Hybrid UX
Primary Goal: restore useful Home breadth and make Report, Check, Track, Learn, Help, and the footer feel like one coherent product without removing capabilities.
Primary User: a citizen using ThreadZero to understand, prepare, check, track, learn, or find the right official next step.
Success Metric: at 1440×900, each core workspace exposes its purpose, primary task, and next action above the fold without horizontal overflow.
Time Horizon: one controlled release.
Current Version: V7.3.
Constraints: static Next.js export, Bun 1.3.14, no backend, no auth, no database, no uploads/OCR/RAG/model calls, no external writes, no real government lookup, preserve existing URLs and existing deterministic demo behavior.
Out of Scope: new product capabilities, chatbot consolidation, analytics, government integrations, data-model redesign, Report/Track business-logic changes, deleting Check modes or Learn/Help routes.
Failure Conditions: useful Home sections remain missing; Report gains duplicate H1s; Track loses preparation/reference functionality; Learn/Help routes become inaccessible; Check structure regresses; any public route fails build/export; safety boundaries become false or misleading.
What Must Be Verified: all tests; TypeScript; static generation; export integrity; public Home/Report/Check/Track/Learn/Help HTTP delivery; all seven Check modes remain reachable; five Report stages remain reachable; Learn and Help route families remain present; mobile reflow and 44px targets by source/browser evidence available in the environment.
Review Date: 2026-09-06.

## Design Direction

Approved direction: Hybrid — civic/government-quality structure plus modern product polish.

The V7.4 design anchor is the current Check workspace: clear breadcrumb, strong page purpose, concise supporting copy, a stable workspace navigator, and a focused task area. Other workspaces should borrow that hierarchy where appropriate without becoming visual clones.

## Home

Restore the useful breadth removed in V7.3. Home order:

1. Hero + incident timeline.
2. Four-step How it works strip.
3. Citizen services / choose what you need.
4. Evidence connected to the incident / evidence-to-timeline explainer.
5. Learning Corner / featured resources.
6. Footer.

Restore these sections from `backup/main-pre-v7.3-simplification-20260830/src/components/home.tsx` while preserving the current decision to omit the `Independent concept` eyebrow above the Home H1.

Home must remain a gateway, not become a second Learn or Help page. Restored cards must keep their existing routes/actions and should be visually grouped with restrained borders and consistent section rhythm.

## Report

Keep all five existing stages and adaptive report logic.

Add one page-level masthead before the stepper:

- H1: `Prepare a cybercrime report`.
- Intro: `Organise what happened, important details, evidence, and the timeline before continuing to the appropriate official destination.`
- One calm boundary sentence, not status chips: ThreadZero prepares information locally and does not submit to official systems.

Because the page-level masthead becomes the single H1, each step heading changes from H1 to H2. Keep the step eyebrow (`Step 1 of 5 · What happened?`, etc.) and stage-specific intro copy.

The stage rail and all state/validation behavior remain unchanged except for spacing required by the new masthead.

## Check

Check remains the reference pattern and should not be structurally redesigned in V7.4.

Preserve:

- all seven modes;
- current page masthead;
- current Check tool rail;
- current grouped Overview launcher;
- current `Report or take action` bounded action group;
- deterministic fixtures and result boundaries.

Only shared spacing/token fixes may affect Check if they are required for cross-workspace consistency.

## Track

Preserve both meanings of Track:

1. local preparation progress;
2. deterministic demo/browser-saved reference tracker.

Reduce vertical density in the preparation block by approximately 35–45% at desktop widths.

Replace the current split `five stages + 280px Evidence readiness sidebar` composition with one compact bounded panel:

- compact heading row with `Preparation progress` and `Continue preparation`;
- five-stage horizontal progress line;
- one horizontal Evidence readiness summary row: `Have`, `Missing`, `Not sure`.

On mobile, stages may stack or scroll while preserving 44px targets and no horizontal page overflow.

Keep the truthful boundary that ThreadZero cannot see NCRP/police/government case status. Keep the reference tracker and demo status below the progress block.

## Learn

Learn should become a true workspace family rather than a horizontal tab bar followed by repeated cards.

Desktop family navigation becomes a left rail inspired by Check. Mobile uses a `Choose Learn section` select. Routes preserved:

- Overview
- Safety
- Awareness
- Advisories
- Daily digest
- Training
- Media
- Accessibility

The rail is used on the Learn landing page and secondary Learn pages so the family stays visually consistent after navigation.

Learn Overview hierarchy:

1. Page masthead with a larger contextual illustration integrated into the hero, not a small detached image.
2. `What do you need help learning?` task navigator with the four existing situation paths.
3. Latest alerts: one featured current alert plus two secondary alerts, editorial rather than card-grid presentation.
4. Guided learning pathways / resource families.
5. Compact resource directory.
6. Official references.

Use mixed presentation types: hero, task rows, editorial alert list, horizontal learning modules, compact directory. Avoid turning every item into a bordered card.

## Help

Help becomes an action-first support workspace with the same family-rail principle.

Desktop family navigation:

- Help options
- Frequently asked questions
- Portal feedback
- Complaint / escalation help

Mobile uses `Choose Help section`.

Help Overview hierarchy:

1. Page masthead with integrated large help illustration.
2. Immediate urgent financial-fraud band: `Money lost? Call 1930 manually` plus official portal action.
3. `What kind of help do you need?` with three normal paths: financial-fraud/report preparation, portal/concept feedback, grievance/escalation guidance.
4. Common questions / secondary help shortcuts.
5. Official help destinations.
6. Official references.

The urgent band appears before ordinary help choices. It must not imply ThreadZero places calls or submits reports.

## Footer Guidance Visual

Keep creator socials and navigation unchanged.

Redesign only the right `Find the right next step` footer panel:

- larger/wider panel treatment;
- illustration becomes an absolute bottom-right/background composition taking roughly 50–60% of the panel width on desktop;
- use a subtle civic-blue/white gradient or overlay so text remains legible;
- copy and CTA remain foreground HTML;
- mobile stacks copy above a larger lower illustration rather than squeezing the image into a narrow side column.

Do not rasterize text into the image.

## Architecture

### Existing owners preserved

- `src/components/home.tsx` owns Home.
- `src/components/flow-route.tsx` owns Report.
- `src/components/check-workspace.tsx` owns Check and remains the design reference.
- `src/components/track.tsx` owns Track.
- `src/components/public-route.tsx` owns secondary Learn/Help routes.
- `src/components/learning-help-v73.tsx` is replaced/renamed conceptually by V7.4 landing owners.
- `src/components/shell.tsx` owns the footer.
- `src/lib/navigation.ts` remains the source of Learn/Help family route membership.

### New unit

Create `src/components/workspace-rail.tsx` as the reusable navigation surface for Learn and Help route families. It consumes `navigationContextFor(routeId)`, renders a sticky desktop rail and mobile select, and preserves existing route destinations. It does not replace Check's purpose-built rail.

### Landing surfaces

Update the Learn/Help landing owner to V7.4 (`learning-help-v74.tsx`) and update `route-screen.tsx` imports. Secondary Learn/Help pages remain rendered through `PublicRoute`, but PublicRoute uses `WorkspaceRail` for context families `learn` and `help` instead of the horizontal `WorkspaceNavigator`.

## Safety / Content Boundaries

- Keep `1930` manual-call language.
- Keep `cybercrime.gov.in` as the real official destination.
- Never imply real case status, fund freezing, real fraud determination, government approval, or submission.
- Do not add prototype-style chip rows merely to prove safety boundaries.
- Maintain one visible H1 per page.
